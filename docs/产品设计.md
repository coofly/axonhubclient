## 定位

`AxonHubClient` 是用于管理 AxonHub 实例的 Python client 和 CLI。它是 Agent 操作 AxonHub 的标准化管理层，而不是上游资源采集器。

它负责把外部已经获得、已经授权使用的上游 API endpoint、API key、支持模型等信息写入并管理为 AxonHub 中的 channel、model、routing 和 usage 对象。

它不负责：

- 搜索、采集、注册或获取上游 API 资源。
- 判断外部资源来源是否合法。
- 在未确认的情况下执行真实写操作。
- 读取、展示、复制或导出 API key 明文。

调用方应确保输入的 endpoint、凭证和模型信息具有合法授权。

## 接口策略

当前认证和接口策略收敛为 Admin Token 模式：

- `auth login` 登录任意 AxonHub 实例，并把默认 session 保存到当前用户配置目录。
- 后续命令自动读取默认 session。
- 主要请求 `/admin/graphql`。
- 公共状态接口使用 `/admin/system/status`。
- `/openapi/v1/graphql` 仅作为后续参考，不作为当前主实现路径。

CLI 基础形态为：

```bash
axonhubclient <resource> <action>
```

Python client 按资源领域暴露能力，单个方法尽量对应一个 GraphQL query、mutation 或 REST endpoint。新增方法前应先映射前端 GraphQL 操作和后端 schema，避免凭空设计字段。

## 安全模型

默认安全原则：

- 读操作可直接执行。
- 写操作默认 dry-run。
- 只有显式传入 `--confirm` 才提交真实 mutation。
- 删除、清理 disabled key、测试上游接口等高风险操作必须在 dry-run 中标记影响范围。
- 输出中所有常见敏感字段必须脱敏。
- 查询层避免选择不必要的明文字段。

已明确的敏感字段边界：

- 渠道查询不请求 `Channel.credentials`。
- 渠道查询不请求 `disabledAPIKeys.key`。
- API Key 主体查询不请求明文字段 `key`。
- `auth login` 不保存密码，默认不打印 token。

如后续开放 API Key / Profile 写操作，应继续遵循默认 dry-run、强确认、脱敏输出和最小字段查询原则。API key 明文只允许在创建后一次性显示，并且必须由用户明确请求。

## 能力分层

### 资产盘点

让 Agent 或管理员先理解 AxonHub 当前状态，包括：

- 登录状态和当前用户。
- 渠道、渠道标签、渠道类型分布和渠道详情。
- 模型、模型关联规则和未关联模型。
- API Key / Profile 只读摘要、配额和模板。
- 用量、请求、日志、Trace 和渠道健康情况。
- 实例级 inventory summary。

### 管理写操作

用于把已经授权的外部资源安全写入 AxonHub，并维护现有对象状态，包括：

- 渠道创建、批量创建、导入、更新和排序。
- 渠道启停、归档、恢复和删除。
- 渠道 endpoints 保存。
- 渠道模型同步。
- 渠道内 API key 启停和 disabled key 记录清理。
- 模型创建、批量创建、更新、启停、归档、恢复和删除。
- 模型关联规则整体替换和细粒度编辑。

这类能力必须保持可预览、可确认、可脱敏。

### 验证与排障

用于确认管理动作是否可用，并辅助定位问题：

- 渠道连通性测试。
- 渠道内 API key 测试。
- 请求日志、用量日志和 Trace 只读检索。
- 渠道健康诊断。
- 只读 smoke test。

测试类命令虽然属于验证动作，但可能真实请求上游接口并消耗额度，因此仍按写操作确认模型处理。

### 路由与成本优化

后续可基于 AxonHub 内部数据给出路由优化建议，第一版只输出建议，不自动修改路由。

优化建议应考虑：

- 成本。
- 成功率。
- 延迟。
- 支持模型。
- channel 状态。
- channel tags。
- ordering weight。

候选能力包括 `routing inspect`、`routing suggest` 和面向成本/稳定性的渠道排序建议。

### 组织和系统管理

后续可继续补齐项目、用户、角色和系统配置盘点。高影响系统操作，例如 backup、restore、cache cleanup、GC cleanup，应先补方案和风险分级，再决定是否开放 CLI 写入口。

## 实现结构

当前仓库采用 flat layout。公共入口保留兼容门面，具体实现按资源领域拆分，避免单文件继续膨胀。

```text
axonhub_client/
  client.py                    # AxonHubClient 门面和资源 API 聚合
  client_admin.py              # auth、api-keys、channels、models
  client_observability.py      # usage、requests、usage logs、traces
  client_management.py         # diagnostics、smoke test、inventory
  client_utils.py              # connection/filter 辅助函数
  cli.py                       # CLI parser 和命令注册
  cli_handlers.py              # 写操作和复杂命令处理器
  cli_helpers.py               # JSON 输入、模型和渠道参数归一化
  cli_session_output.py        # session、登录和输出脱敏
  queries.py                   # GraphQL 常量兼容导出
  graphql_queries/             # 按领域拆分的 GraphQL query/mutation
  transport.py                 # REST / GraphQL transport
tests/
docs/
pyproject.toml
```

## 与 Skill 的关系

Skill 是 `AxonHubClient` 项目的配套能力，用于指导 Agent 优先使用本项目提供的 CLI / Python client 管理 AxonHub，而不是把 `AxonHubClient` 视为 Skill 的附属代码。

浏览器工具只作为辅助：

- 获取或刷新 admin token。
- 对照 UI 验证接口行为。
- 当接口行为不明时观察前端请求。

常规管理动作应通过 CLI / Python client 完成，而不是手动点击后台页面。
