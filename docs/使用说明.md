# AxonHubClient 使用说明

本文档是 `axonhubclient` CLI 的完整命令和参数说明，只记录如何调用命令、输入参数和确认规则。产品定位、能力边界和演进原则见 `docs/产品设计.md`；任务状态见 `docs/项目看板.md`。

命令默认面向 AxonHub Admin API；除 `auth login`、`auth logout` 外，其它命令使用当前用户配置目录中的默认 session。

## 运行方式

首次使用先登录：

```powershell
axonhubclient auth login --url https://axonhub.example.com --username admin@example.com
```

`auth login` 缺少 `--url`、`--username` 或 `--password` 时会交互式询问；密码输入不会回显。登录成功后保存默认 session，不保存密码。

默认 session 保存位置：

- Windows：`%APPDATA%\AxonhubClient\session.json`
- macOS：`~/Library/Application Support/AxonhubClient/session.json`
- Linux：`$XDG_CONFIG_HOME/axonhubclient/session.json` 或 `~/.config/axonhubclient/session.json`

## 全局参数

| 参数 | 说明 |
| --- | --- |
| `--context-project-id <id>` | 设置 `X-Project-ID` 请求上下文。 |
| `--timeout <seconds>` | 请求超时时间，默认 `30`。 |
| `--json` | 输出完整 JSON 响应。 |

列表类筛选参数统一使用子命令局部的 `--project-id`；它不同于全局请求上下文 `--context-project-id`。

## 输入和确认规则

- 读操作直接执行。
- 写操作默认 dry-run；必须显式传入 `--confirm` 才提交真实 mutation。
- dry-run 输出统一包含 `dryRun`、`operation`、`effect`、`variables`。
- 删除渠道、删除模型、清理 disabled key 等高风险操作仍使用 `--confirm`，dry-run 会标记影响范围。
- CLI 不请求 `Channel.credentials`，不读取 disabled API key 或 API Key 主体的明文字段。
- CLI 输出会对 `apiKey`、`apiKeys`、`key`、`keys`、`token`、`password` 等字段脱敏。
- `--input-json`、`--settings-json`、`--endpoints-json`、`--association-json`、`--associations-json`、`--proxy-json` 接收 JSON 字符串。
- `--api-key`、`--supported-model`、`--manual-model`、`--tag`、`--status`、`--type`、`--source` 等可重复参数可以传多次；文档另有说明时，也支持逗号、换行或 JSON array。

## Auth

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `auth status` | 无 | 读取 `/admin/system/status`。 |
| `auth login` | `--url <url>`、`--username <name>`、`--password <password>`、`--json` | 使用账号密码登录并保存默认 session。 |
| `auth whoami` | 无 | 读取当前 admin token 对应用户。 |
| `auth logout` | 无 | 清除当前用户默认 session。 |

示例：

```powershell
axonhubclient auth login --url https://axonhub.example.com --username admin@example.com
axonhubclient auth whoami
axonhubclient auth logout
```

## Channels

### 只读命令

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `channels list` | `--first <n>` 默认 `100`、`--after <cursor>`、`--status <status>` 可重复、`--type <type>` 可重复、`--tag <tag>`、`--model <model>` | 分页读取渠道。 |
| `channels get <id>` | `<id>` | 读取单个渠道。 |
| `channels summary` | `--include-archived` | 读取渠道摘要和模型入口。 |
| `channels tags` | 无 | 读取全部渠道标签。 |
| `channels count-by-type` | `--status <status>` 可重复 | 按渠道类型计数。 |

### 写操作

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `channels create` | `--type <type>` 必填、`--name <name>` 必填、`--upstream-base-url <url>` 必填、`--api-key <key>` 可重复、`--oauth-api-key <json>`、`--gcp-region <region>`、`--gcp-project-id <id>`、`--gcp-json <json>`、`--supported-model <model>` 可重复、`--manual-model <model>` 可重复、`--default-test-model <model>`、`--tag <tag>` 可重复、`--auto-sync-supported-models`、`--auto-sync-model-pattern <regex>` 默认空字符串、`--ordering-weight <int>`、`--remark <text>`、`--stream-policy unlimited\|require\|forbid`、`--settings-json <json>`、`--endpoints-json <json>`、`--confirm` | 创建单个渠道；未传 `--confirm` 只输出 dry-run。`--upstream-base-url` 也可写作 `--channel-base-url`。 |
| `channels create-many [input_file]` | `[input_file]` 或 `--input-json <json>` 必填其一、`--confirm` | 按 `BulkCreateChannelsInput` 批量创建渠道。 |
| `channels import [input_file]` | `[input_file]` 或 `--input-json <json>` 必填其一、`--confirm` | 批量导入渠道。 |
| `channels update <id>` | `<id>`、`--input-json <json>` 或 `--input-file <path>`、`--confirm` | 使用完整 `UpdateChannelInput` 更新渠道。 |
| `channels status <id> enabled\|disabled` | `<id>`、目标状态、`--confirm` | 设置单个渠道启停状态；归档和恢复使用 `archive` / `recover`。 |
| `channels enable <ids...>` | 一个或多个渠道 ID、`--confirm` | 批量启用渠道。 |
| `channels disable <ids...>` | 一个或多个渠道 ID、`--confirm` | 批量禁用渠道。 |
| `channels archive <ids...>` | 一个或多个渠道 ID、`--confirm` | 批量归档渠道。 |
| `channels recover <ids...>` | 一个或多个渠道 ID、`--confirm` | 批量恢复归档渠道。 |
| `channels delete <ids...>` | 一个或多个渠道 ID、`--confirm` | 删除渠道，高风险不可逆。 |
| `channels reorder [input_file]` | `[input_file]` 或 `--input-json <json>` 必填其一、`--confirm` | 批量更新渠道排序权重。 |
| `channels endpoints set <id>` | `<id>`、`--endpoints-json <json>` 或 `--endpoints-file <path>`、`--confirm` | 替换渠道 endpoints。 |
| `channels test <id>` | `<id>`、`--model <model>`、`--proxy-json <json>`、`--confirm` | 测试渠道连通性；执行时会真实请求上游接口，可能消耗额度。 |
| `channels keys test <id>` | `<id>`、`--model <model>`、`--confirm` | 逐个测试渠道 API key；执行时会真实请求上游接口，可能消耗额度。 |
| `channels keys disable <id>` | `<id>`、`--key <key>` 必填、`--confirm` | 禁用渠道内单个 API key。 |
| `channels keys enable <id>` | `<id>`、`--key <key>` 必填、`--confirm` | 启用渠道内单个 API key。 |
| `channels keys enable-all <id>` | `<id>`、`--confirm` | 启用渠道内全部 API key。 |
| `channels keys enable-selected <id>` | `<id>`、`--key <key>` 必填且可重复、`--confirm` | 启用渠道内选中的 API key；`--key` 支持逗号、换行或 JSON array。 |
| `channels keys prune-disabled <id>` | `<id>`、`--key <key>` 必填且可重复、`--confirm` | 清理渠道 disabled API key 记录，高风险操作；`--key` 支持逗号、换行或 JSON array。 |
| `channels models sync <id>` | `<id>`、`--pattern <regex>`、`--confirm` | 立即同步渠道 `supportedModels`。 |

`channels create` 的 `--supported-model` 可选：如果手动提供则优先使用；如果省略，CLI 会尝试用上游 API key 请求 OpenAI/NewAPI 兼容 `/models` 端点，自动填充 `supportedModels` 和默认测试模型。自动发现失败时不会回退到占位模型，而是要求显式提供 `--supported-model`。

示例：

```powershell
axonhubclient channels create `
  --type openai `
  --name openai-main `
  --upstream-base-url https://api.openai.com/v1 `
  --api-key "sk-..."

axonhubclient channels create-many docs\examples\channel.bulk-create.json --confirm
axonhubclient channels import docs\examples\channels.import.json --confirm
axonhubclient channels update <channel-id> --input-file docs\examples\channel.update.json --confirm
axonhubclient channels reorder docs\examples\channel.bulk-ordering.json --confirm
axonhubclient channels endpoints set <channel-id> --endpoints-file docs\examples\channel.endpoints.json --confirm
axonhubclient channels models sync <channel-id> --pattern "gpt-.*" --confirm
```

## API Keys

`api-keys` 是只读盘点资源。相关 GraphQL 查询不会选择 API Key 明文字段 `key`；输出仍会经过通用脱敏层。

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `api-keys list` | `--first <n>` 默认 `100`、`--after <cursor>`、`--status enabled\|disabled\|archived`、`--type user\|service_account\|noauth`、`--name <name>`、`--project-id <id>`、`--user-id <id>` | 分页读取 API Key 摘要。默认排除 `noauth`；显式传入 `--type` 时按指定类型查询。 |
| `api-keys get <id>` | `<id>` | 读取单个 API Key 详情和 Profile 配置。 |
| `api-keys quota <id>` | `<id>` | 读取 API Key 各 Profile 的配额窗口和用量。 |
| `api-keys templates` | `--first <n>` 默认 `100`、`--project-id <id>`、`--name <name>` | 读取 API Key Profile 模板。 |

示例：

```powershell
axonhubclient --json api-keys list --status enabled
axonhubclient --json api-keys quota <api-key-id>
axonhubclient --json api-keys templates --project-id <project-id>
```

## Models

### 只读命令

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `models list` | `--first <n>` 默认 `100`、`--after <cursor>`、`--status <status>` 可重复、`--type <type>` 可重复、`--model-id <modelID>`、`--name <name>` | 分页读取模型。 |
| `models get <id>` | `<id>`、`--model-id` | 读取单个模型；传 `--model-id` 时把 `<id>` 作为 modelID 查询。 |
| `models fastest` | `--window day\|week\|month\|allTime` 默认 `day`、`--limit <n>` 默认 `5` | 读取最快模型吞吐排行。 |
| `models rules list <id>` | `<id>`、`--model-id` | 读取模型关联规则。 |
| `models rules preview [id]` | `[id]`、`--model-id`、`--associations-json <json>` 或 `--associations-file <path>` | 预览模型关联渠道；必须提供 `[id]` 或 associations 输入之一，提供 associations 输入后不读取模型。 |
| `models rules unassociated` | 无 | 检测渠道中未关联到模型配置的模型。 |

### 写操作

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `models create` | `--input-json <json>` 或 `--input-file <path>`、`--confirm` | 创建模型；输入为 `CreateModelInput`。 |
| `models create-many` | `--input-json <json>` 或 `--input-file <path>`、`--confirm` | 批量创建模型；输入为 `CreateModelInput` 数组或 `{"models": [...]}`。 |
| `models update <id>` | `<id>`、`--input-json <json>` 或 `--input-file <path>`、`--confirm` | 使用 `UpdateModelInput` 更新模型。 |
| `models status <id> enabled\|disabled\|archived` | `<id>`、目标状态、`--confirm` | 设置单个模型状态。 |
| `models enable <ids...>` | 一个或多个模型实体 ID、`--confirm` | 批量启用模型。 |
| `models disable <ids...>` | 一个或多个模型实体 ID、`--confirm` | 批量禁用模型。 |
| `models archive <ids...>` | 一个或多个模型实体 ID、`--confirm` | 批量归档模型。 |
| `models recover <ids...>` | 一个或多个模型实体 ID、`--confirm` | 批量恢复模型为 `enabled`。 |
| `models delete <ids...>` | 一个或多个模型实体 ID、`--confirm` | 删除模型，高风险不可逆。 |
| `models rules replace <id>` | `<id>`、`--model-id`、`--associations-json <json>` 或 `--associations-file <path>`、`--confirm` | 整组替换 `settings.associations`。 |
| `models rules add <id>` | `<id>`、`--model-id`、`--association-json <json>` 或 `--association-file <path>` 必填其一、`--position <n>`、`--confirm` | 添加单条关联规则；`--position` 为 1-based，默认追加。 |
| `models rules remove <id>` | `<id>`、`--model-id`、`--index <n>` 必填、`--confirm` | 移除 1-based 索引处的关联规则。 |
| `models rules enable <id>` | `<id>`、`--model-id`、`--index <n>` 必填、`--confirm` | 启用 1-based 索引处的关联规则。 |
| `models rules disable <id>` | `<id>`、`--model-id`、`--index <n>` 必填、`--confirm` | 禁用 1-based 索引处的关联规则。 |
| `models rules reorder <id>` | `<id>`、`--model-id`、`--from-index <n>` 必填、`--to-index <n>` 必填、`--confirm` | 调整关联规则顺序，索引为 1-based。 |

细粒度规则编辑会在写回前归一化 `priority`。`models create` 不接受 `status`；创建后如需启用，使用 `models enable` 或 `models status <id> enabled`。

示例：

```powershell
axonhubclient models create --input-file docs\examples\model.create.json
axonhubclient models create-many --input-file docs\examples\models.bulk-create.json --confirm
axonhubclient models update <model-entity-id> --input-file docs\examples\model.update.json --confirm
axonhubclient models rules add <model-entity-id> --association-file docs\examples\model.rule.json --position 1 --confirm
axonhubclient models rules replace <model-entity-id> --associations-file docs\examples\model.associations.json --confirm
```

## Requests

`requests` 是只读排障资源。列表默认只读取摘要、用量摘要和最近执行摘要；单条详情默认不读取请求/响应正文。

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `requests list` | `--first <n>` 默认 `100`、`--after <cursor>`、`--status <status>` 可重复、`--source <source>` 可重复、`--channel-id <id>`、`--project-id <id>`、`--model <model>`、`--trace-id <id>`、`--created-after <time>`、`--created-before <time>` | 分页读取请求日志摘要。 |
| `requests get <id>` | `<id>`、`--include-content` | 读取单个请求日志；`--include-content` 会额外读取 headers、请求正文、响应正文和 chunks。 |
| `requests executions <id>` | `<id>`、`--first <n>` 默认 `100`、`--after <cursor>`、`--status <status>` 可重复、`--channel-id <id>` | 读取请求对应的上游执行记录摘要。 |

示例：

```powershell
axonhubclient --json requests list --status failed --first 20
axonhubclient --json requests list --project-id <project-id> --created-after "2026-06-01T00:00:00Z"
axonhubclient --json requests get <request-id> --include-content
```

| 命令 | 参数 | 说明 |
